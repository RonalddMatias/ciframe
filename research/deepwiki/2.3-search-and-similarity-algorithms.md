This section documents the search, normalization, filtering, similarity ranking, and pagination algorithms implemented in the Flask backend (`main.py`). These algorithms bridge user requests for song discovery with in-memory indexes built from `dataset_final.csv`.

* * *

## 1. Diacritic Normalization (`remover_combinantes`)

To ensure robust text matching across user queries and song metadata (which often contain Portuguese accented characters like `á`, `ê`, `ç`), the system normalizes strings by decomposing unicode characters and stripping combining diacritical marks (`Mn` category).

The function is defined as:

`def remover_combinantes(string):    string = unicodedata.normalize('NFD', string)    return u''.join(ch for ch in string if unicodedata.category(ch) != 'Mn')`
*   **Input**: A raw string (e.g., search queries or artist/song names).
*   **Process**: Converts string to Normalization Form Decomposition (NFD) using Python's `unicodedata` module, then filters out any character whose category is Nonspacing Mark (`Mn`).
*   **Usage**: Applied during text search queries [main.py 119](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L119-L119) and target text fields [main.py 130](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L130-L130)

## 2. Token Matching and Text Search (`/search`)

The `/search` endpoint implements a multi-token containment search over artist names and song titles [main.py 114-142](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L114-L142)

### Data Flow and Search Process

1.   Query parameters are extracted from `request.args`, including `key` (search terms) and optional `generos` tags [main.py 116-118](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L116-L118)
2.   The search string is converted to lowercase and normalized using `remover_combinantes`, then split into individual space-separated tokens (`keys`) [main.py 118-119](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L118-L119)
3.   The global music collection is filtered by requested genres using `apply_filtro`[main.py 125](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L125-L125)
4.   For each song in the filtered collection, a combined text string of `nome_artista` and `nome_musica` is constructed, normalized, and split into tokens (`text_list`) [main.py 129-130](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L129-L130)
5.   A song matches only if **all** search keys are present in `text_list` (`all(key in text_list for key in keys)`) [main.py 131](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L131-L131)

## 3. Genre Filtering (`apply_filtro`)

When users specify genre constraints (via `generos` query parameters), the search and similarity engines restrict the candidate song collection.

*   **Behavior**: `apply_filtro` takes a collection of `Musica` objects and a list of allowed genres (`generos_key`), returning only those songs whose `genero` attribute matches one of the allowed genres [main.py 125](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L125-L125)[main.py 205](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L205-L205)
*   **Integration**: Used prior to text matching in `/search`[main.py 125](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L125-L125) and prior to sequence similarity ranking in `get_similares_por_sequencia`[main.py 205](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L205-L205)

Sources: `main.py:125`, `main.py:205`

## 4. Chord Intersection and Difference Ranking (`get_similares`)

The `/similares` endpoint handles similarity queries based on chords, source music IDs, or chord sequences [main.py 170-201](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L170-L201)

### Modes of Similarity

1.   **Explicit Chords (`acordes_tag`)**: Extracts a comma-separated list of chords directly from the request [main.py 185-186](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L185-L186)
2.   **Reference Song (`id_musica_tag`)**: Looks up a reference `Musica` object from `musicas_dict` and inherits its `acordes` list [main.py 187-189](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L187-L189)
3.   **Chord Sequence (`sequencia_tag`)**: Replaces commas and matches against known famous sequences [main.py 190-194](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L190-L194)

Once a set of target chords or sequence ID is established, `get_similares` ranks songs by calculating chord overlap (intersection and difference against the target song's chord set).

## 5. Famous-Sequence Matching (`get_similares_por_sequencia`)

Famous chord progressions (such as `BmGDA`, `CGAmF`, `EmG`, etc.) are mapped to integer identifiers in `sequencias`[main.py 40-45](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L40-L45):

`sequencias = {    'BmGDA' : 0,    'CGAmF' : 1,    'EmG' : 2,    'CA7DmG7' : 3,    'GmF' : 4,    'CC7FFm' : 5}`
*   **Process**: When a sequence is queried, `get_similares_por_sequencia` filters the song collection by genre and checks whether the string representation of `id_seq` exists within `musica.seqs_famosas`[main.py 203-209](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L203-L209)
*   **Metadata Mapping**: These numeric sequence IDs correspond to human-readable names and chord breakdowns defined in `data/mapeamento_sequencias_famosas.txt` (e.g., ID `0` corresponds to `Sequência de Bm` / `Bm - G - D - A`) [data/mapeamento_sequencias_famosas.txt 1-6](https://github.com/joaoarthurbm/ciframe/blob/fb970019/data/mapeamento_sequencias_famosas.txt#L1-L6)

Sources: `main.py:40-45`, `main.py:203-214`, `data/mapeamento_sequencias_famosas.txt:1-6`

To prevent large payloads on broad search or similarity requests, API endpoints return results divided into pages.

*   **Page Size**: Defined by `TAM_PAGINA = 100`[main.py 35](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L35-L35)
*   **Usage**: Applied to output collections in `/search`[main.py 142](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L142-L142) sequence similarities [main.py 196](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L196-L196) and general similarities [main.py 201](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L201-L201)
*   **Implementation**: Slices the resulting list based on the requested `pagina` query parameter (defaulting to page `1` if omitted) [main.py 117](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L117-L117)[main.py 176](https://github.com/joaoarthurbm/ciframe/blob/fb970019/main.py#L176-L176)
