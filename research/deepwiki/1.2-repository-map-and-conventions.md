## Purpose and Scope

This document provides a technical tour of the repository layout, top-level directories, and core engineering conventions for `ciframe`. It details the structural organization of backend modules, frontend assets, data stores, offline scripts, and documentation, providing developers with a map of code entities and architectural rules.

## Top-Level Directory and File Tour

The project root contains configuration files, deployment scripts, and major subdirectories separating the backend, frontend, data pipeline, and documentation.

```
ciframe/
├── main.py
├── musica.py
├── Dockerfile
├── requirements.txt
├── AGENTS.md
├── README.md
├── CONTRIB.md
├── .playground
├── data/
├── scripts/
├── static/
└── docs/
```

### Core Backend Files

*   `main.py`: The single-file Flask application containing all REST endpoints, startup in-memory indexing logic, string normalization functions, and search/similarity algorithms [AGENTS.md 9-11](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L9-L11)
*   `musica.py`: The domain model definition module encapsulating song properties, chord cleaning (`limpa_cifra`), and data formatting logic.

### Major Subdirectories

*   `data/`: Contains raw and processed datasets, notably `data/top/dataset_final.csv`, which serves as the primary read-only data source for the application [AGENTS.md 10-11](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L10-L11)
*   `scripts/`: Offline data processing utilities, R scripts, parsers, and scrapers used to build and normalize the dataset [README.md 1-10](https://github.com/joaoarthurbm/ciframe/blob/fb970019/README.md?plain=1#L1-L10)
*   `static/`: The complete AngularJS 1.4.9 client-side single-page application (SPA), including templates, controllers, directives, and CSS assets [AGENTS.md 12-15](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L12-L15)
*   `docs/`: Project documentation, including Architecture Decision Records (`docs/adr/`) and RePPIT feature specifications (`docs/features/`) [AGENTS.md 15](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L15-L15)

## Core Architectural Conventions

The application enforces specific architectural patterns that govern state management, data persistence, and API serialization.

### 1. In-Memory Dataset and No Database

The backend does not use a relational or NoSQL database. Instead, `main.py` loads the entire dataset from `data/top/dataset_final.csv` into memory as Python dictionaries and lists once during application startup [AGENTS.md 9-11](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L9-L11)

### 2. CSV Reload Requirement

Because the dataset is indexed exclusively at startup, modifying any files under `data/top/*.csv` requires an explicit application restart for changes to take effect in API responses [AGENTS.md 43-45](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L43-L45)

### 3. Legacy Serialization (`json.dumps`)

API endpoints do not use Flask's modern `jsonify` utility. Instead, responses are serialized explicitly using `json.dumps(...)` and returned as raw strings with a `text/html` content type. This is an intentional legacy behavior; modifying it constitutes a breaking API change [AGENTS.md 46](https://github.com/joaoarthurbm/ciframe/blob/fb970019/AGENTS.md?plain=1#L46-L46)
